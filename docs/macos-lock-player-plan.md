# Плеер macOS на экране блокировки: план, без реализации

Состояние проверки: 2026-11-08, локальный Mac — macOS 26.6.2.

## Что уже есть

В Pencil сохранены два варианта внутри `JyiFo`: большой (`ZiVWd`) и компактный (`S0K86`). Обои не заменяются. Это дизайн карточки Лада, а не доказательство того, что macOS предоставляет такой системный layout.

В коде есть Swift-мост `lad-nowplaying`, который публикует метаданные через `MPNowPlayingInfoCenter` и получает команды через `MPRemoteCommandCenter`. Он не создаёт окна с карточкой C4. Публикация Now Playing сама по себе не подтверждает появление выбранного макета на заблокированном Mac.

## Кандидат для своей карточки

AppKit документирует `NSWindow.canBecomeVisibleWithoutLogin`: окно может отображаться у окна входа. Поэтому следующий шаг — отдельный минимальный AppKit-прототип панели в уже открытой пользовательской сессии. Нельзя обещать рабочую интерактивность на экране блокировки по одному этому свойству: положение окна, доставка нажатий, несколько мониторов и сон требуют проверки на настоящем Mac.

Источники:

- [NSWindow.canBecomeVisibleWithoutLogin](https://developer.apple.com/documentation/appkit/nswindow/canbecomevisiblewithoutlogin)
- [MPNowPlayingInfoCenter](https://developer.apple.com/documentation/mediaplayer/mpnowplayinginfocenter)

Начальный экран FileVault до входа пользователя находится вне этого сценария.

## Что перенести из Android

- Два размера карточки с одной логикой управления и одинаковой симметрией кнопок.
- На паузе — доступность недавней медиа-сессии; отметка времени на событии, проверка при показе, без периодического опроса блокировки.
- Тап по обложке — режим синхронного текста; маленькая обложка переносится в строку названия. Текст синхронизируется с реальным плеером, обои остаются прежними.
- Стекло C4 через нативный материал; никакой фоновой паутинки или постоянных 60 FPS для карточки.
- Скрытие на разблокировке, сне и смене пользовательской сессии; фоновые часы/прокрутка текста в этот момент останавливаются.
- Панель не забирает клавиатурный фокус у пароля. Действия ограничены управлением музыкой; доступ к библиотеке и настройкам требует разблокировки.

## Что проверить до реализации дизайна

1. Пустая нативная панель видна после настоящей блокировки уже вошедшего пользователя.
2. Play/pause доставляются без разблокировки; пароль и Touch ID продолжают работать.
3. Панель корректно скрывается при разблокировке и не задерживает сон дисплея.
4. Работают внешний монитор, смена масштаба, сон/пробуждение и переключение пользователя.
5. При неуспехе прототипа не подменять результат обычным окном поверх рабочего стола: отдельно согласовать доступный вариант.

Перед подключением панели нужно убрать синхронную загрузку обложек `Data(contentsOf:)` с главного потока существующего Swift-моста. Нативная панель должна получать готовое состояние/кэш обложки и только отправлять команды существующему движку Лада.

Код macOS в рамках Android-исправления не изменялся; живой прототип блокировки Mac не запускался.
