# Участие в разработке

Сначала посмотри [архитектуру](docs/architecture.md) и [инструкцию по сборке](docs/development.md).

1. Для существенного изменения открой issue с ожидаемым поведением и платформой.
2. Внеси изменение в отдельной ветке. Общую логику воспроизведения проверяй на всех затронутых реализациях.
3. Запусти относящиеся к изменению тесты и обнови пользовательскую документацию.
4. В pull request опиши проблему, новое поведение и способ проверки. Для UI приложи снимок из режима знакомства без данных аккаунта.

Не добавляй в git сессии, ключи подписи, `local.properties`, логи с аккаунтом и готовые бинарные сборки. Для них предусмотрены `.gitignore` и проверка публикации. Соавторов указывай через `Co-authored-by`, когда они участвовали в изменении; существующие trailers сохраняй.

Вклады в собственный код проекта принимаются под **AGPL-3.0-only**. Не меняй лицензии или заголовки сторонних компонентов.
